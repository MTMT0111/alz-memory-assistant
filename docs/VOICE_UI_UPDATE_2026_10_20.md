# 语音页面与反馈更新 · 2026-10-20

本次更新聚焦 `/conversation` 的网页语音体验。它是陪伴交互原型，也用于验证未来设备交互；不能作为真实硬件在线、患者已听见或医疗效果的证明。

## 行为变化

- 主按钮明确显示「开始说话」「结束并发送」「打断并说话」。录音期间显示秒数，60 秒自动结束并发送；取消录音不上传。
- 区分麦克风权限等待、识别、回复等待、语音准备与实际播放。只有播放事件发生后才显示正在朗读。
- 停止会取消待处理的识别或朗读，并忽略迟到的响应、麦克风权限结果及浏览器朗读事件。等待聊天回复时，「本次不朗读」只关闭自动朗读，文字回复仍会保留。
- 识别和朗读请求有 45 秒等待上限，聊天请求有 60 秒等待上限。超时不保证服务端未处理：失败时保留输入内容并提示避免连续重试。
- 中文输入法确认候选词不会误发送；请求处理中拦截重复发送。语音发送结束后不会主动唤起文字键盘。
- 失败提示保持可见。设备朗读没有开始时会恢复操作，不永久卡在等待状态。ASR 配置失败不会禁用独立的 TTS 链路。
- 页面采用可读状态文字、较大触控区域、保留焦点轮廓与减少动态效果支持。工程诊断仅在显式调试模式出现，调试链接保留当前患者。
- 主语音链路的 STT 和 TTS 网络请求移至线程执行，避免阻塞异步服务器的事件循环。

## 与产品方向的关系

先把可停止、能理解、失败可恢复的陪伴对话做好，再复用后端接入微信小程序与硬件。保留文字替代路径，不默认持续监听。语音结束后会上传到识别服务，文字进入对话记录，页面直接说明这一点。

沿用温和陪伴、短句、熟悉素材与家属核实的方向。患者口头说「吃过了」不能据此升级为已经核实的用药事实；陪伴对话不能被未经验证的记忆考试替代。上述边界不由本次界面更新提供临床有效性证明。

## 验证

```sh
node scripts/test_voice_ui.cjs
python scripts/test_stt_responsiveness.py
```

前者使用真实前端脚本和可控异步事件，覆盖重复点击、取消/迟到响应、播放状态、关闭朗读、60 秒录音、错误保留、退出清理、输入法与失败草稿恢复。后者在无真实服务调用的条件下验证 STT/TTS 不阻塞事件循环，以及识别不可用/空结果的返回契约。

隔离数据库的浏览器预览验证了 320、390 和 1440 像素视口及文字对话流程，无横向溢出。浏览器视口检查不等于真实手机、麦克风、扬声器或手环验收。

## 当前限制

本次本地环境的 `OPENAI_API_KEY`、`MINIMAX_API_KEY`、`MINIMAX_GROUP_ID` 仍为示例占位值。因此真实云端语音识别与朗读未验收；配置有效凭据后，应使用无个人信息的测试语句完成端到端验证。密钥只应保存在部署环境，不能写入仓库或前端。

停止客户端等待不等于撤销服务端已经接收的请求。此次更新也没有解决既有的全站权限、音频访问控制或真实家庭试用前的数据治理问题，不能据此直接开放真实患者使用。
