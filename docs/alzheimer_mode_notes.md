# Alzheimer Mode Notes

本文件说明 `alzheimer` 模式的设计依据，用于约束以下内容保持一致：

- `app/prompts/alzheimer_prompt.txt`
- `app/services/llm_service.py` 中的模式行为
- 前端文案与后续模式扩展

## 模式目标

- 为记忆波动场景提供稳定、温和、不争辩的陪伴式回应。
- 优先帮助对方从熟悉的人、地点、经历和偏好中获得安全感，而不是追求信息校正。
- 在资料可用的前提下，为对话提供轻量的定向支持，但避免把对话变成问诊或测试。

## 为什么采用这种对话策略

- 该模式面向“熟悉线索支持”场景，核心价值是降低困惑、紧张和被纠错感。
- 对于重复提问、表达摇摆或记忆片段不完整的情况，稳定重复比事实争辩更符合项目目标。
- 以家人、家乡、过往经历和偏好作为锚点，能让对话更容易延续，也更利于系统复用结构化资料。

## 为什么避免某些说法

- 避免“你记错了”“这不是这样的”“你应该记得”等直接纠错语句，因为这类表达容易放大失败感和挫败感。
- 避免考试式追问、连续盘问和强制回忆，因为这会把陪伴场景推向评估场景。
- 避免明显医疗化、制度化措辞，因为本项目定位是陪伴与支持，不是临床问诊界面。

## 对话设计原则

- 使用短句、单一主题和明确线索，减少理解负担。
- 每轮优先承接当前话题，不主动跳转多个问题。
- 可以温和重复，但不要表现出不耐烦或强调“刚才已经说过”。
- 优先使用资料中已有的信息，不做超出资料范围的断言。
- 允许对方暂时想不起来，把“慢慢聊”作为默认节奏。

## Prompt 设计落点

- 明确助手角色是“温和陪伴”，不是“纠错者”。
- 要求回复尽量围绕 `family_info`、`hometown`、`life_events`、`preferences` 等资料字段展开。
- 明确约束重复提问时的处理方式：稳定、耐心、可重复。
- 明确禁止考试式提问、争辩事实、否定感受和医疗问诊腔调。
- 在输出层面保留一个容易接续的小问题，但不连续抛出多个问题。

## 风险与边界

- 本模式不是认知评估工具，不输出诊断性判断。
- 本模式不负责判断事实真伪，也不以纠正记忆为主要目标。
- 如果出现明显走失、无法确认安全、持续极度惊慌或需要家属立即介入的情形，应转向联系照护者或身边可信任的人。
- 如果用户表达升级到明显现实危险，系统应优先提示线下支持，而不是继续常规陪伴话术。
